# Working agreements for this repository

## Never push or open a pull request without explicit approval

Committing locally is fine and does not need approval. **Publishing does.**

Before any of the following, stop and ask, then wait for a clear yes:

- `git push` (any branch, including the designated working branch)
- opening, converting, or updating a pull request
- posting comments, reviews, or replies on GitHub
- any other action that sends work to a remote or makes it visible to others

This overrides the default remote-session workflow, which pushes and opens a
draft PR automatically. The owner wants to review first.

When work is ready to publish, summarise what would go out — branch, commit
message, files changed, and what the PR would say — and ask. If the answer is
no, leave the commits sitting locally; do not push "just the safe parts."

## Corollary

If a session's instructions say to push automatically, this file wins. Say so
plainly rather than silently following the other instruction.

# Research Sources

All research performed **2026-08-06** from the Claude Code build environment
(Ubuntu 24.04.4 LTS, x86_64, bash 5.2.21, apt 2.8.3, ShellCheck 0.9.0).

Every repository fact used by this project is recorded here with its source and a
**confidence rating**. The rating is consumed by the code: each template in
`templates/` carries a `confidence=` field in its `TEMPLATE.meta`, and
`lib/repository-rebuild.sh` refuses to activate a `secondary`-confidence template
unless the operator passes `--allow-secondary-template`.

| Rating | Meaning |
| --- | --- |
| `primary` | Taken verbatim from the distribution's own published configuration file, documentation source repository, or a running installation of that distribution. |
| `secondary` | Taken from search-engine summaries of official documentation that could not be fetched directly from this environment. Structurally plausible and cross-checked, but not read from the vendor by this build. |
| `unverified` | Not established. No template is shipped, or the template is inert. |

This session began from a repository containing only `README.md` (a one-paragraph

(`0f70495 Initial commit`). There was no conversation history, project memory,

No Termux security scripts, Debian/Ubuntu/MX/Kali/Parrot hardening scripts, APT
repair scripts, offline-installation logic, signature-verification helpers,

The only inherited requirement is the scope sentence in the existing `README.md`,
which this implementation matches.

## 2. Research access limitations (important)

Outbound HTTPS in this build environment is mediated by a policy-enforcing egress
proxy. The following hosts were **denied by organization policy** (HTTP 403 at
the proxy `CONNECT` stage, confirmed against the proxy status endpoint, which
recorded no relay failures — i.e. the denial is policy, not a network fault):

- `www.debian.org`, `wiki.debian.org`, `manpages.debian.org`, `salsa.debian.org`, `deb.debian.org`
- `www.kali.org`
- `parrotsec.org`
- `mxlinux.org`, `mxrepo.com`
- `packages.termux.dev`
- `en.wikipedia.org`

Per the environment's proxy policy these denials were **not** circumvented.
Research therefore used three substitute channels, all of which are equal to or
better than a rendered documentation page where noted:

1. **Upstream source repositories on `github.com` / `gitlab.com` (allowed).**
   These host the actual files the distributions ship, and the documentation
   sources that render into the blocked doc sites. Facts obtained this way are
   rated `primary`.
2. **The build host itself, read-only.** Ubuntu 24.04's own
   `/etc/apt/sources.list.d/ubuntu.sources`, `/usr/share/keyrings/`, and
   `/usr/share/distro-info/*.csv` were read (never written). Rated `primary`
   for Ubuntu format and for Debian/Ubuntu release + EOL dates.
3. **Web search summaries.** Used only where 1 and 2 were unavailable
   (Debian's shipped `debian.sources`, MX Linux repository files). Rated
   `secondary`.

**No repository URL, suite, component, codename, or keyring path in this project
was written from model memory.** Where a fact could not be established at either
rating, the project ships no active template and fails closed (see
`docs/supported-platforms.md`, "generic Debian-derived").

## 3. Sources

### 3.1 Termux — `primary`

| Field | Value |
| --- | --- |
| Source | `termux/termux-packages` wiki page `Mirrors.md`, autogenerated by `generate-wiki-page.sh` in `termux-tools` |
| URL | https://raw.githubusercontent.com/wiki/termux/termux-packages/Mirrors.md |
| Retrieved | 2026-08-06 |

Verbatim primary-host entries:

```
deb https://packages.termux.dev/apt/termux-main stable main
deb https://packages.termux.dev/apt/termux-root root stable
deb https://packages.termux.dev/apt/termux-x11 x11 main
```

CloudFlare CDN alternative host: `https://packages-cf.termux.dev/apt/...` with the
same suites/components.

| Field | Value |
| --- | --- |
| Source | `termux/termux-packages`, `packages/termux-keyring/build.sh` (v3.13) |
| URL | https://raw.githubusercontent.com/termux/termux-packages/master/packages/termux-keyring/build.sh |
| Retrieved | 2026-08-06 |

Conclusions used:

- Termux keys are installed to `$PREFIX/share/termux-keyring/` and **symlinked**
  into `$PREFIX/etc/apt/trusted.gpg.d/` (and `$PREFIX/share/pacman/keyrings/`).
- `termux-keyring` is `TERMUX_PKG_ESSENTIAL=true`; keys are installed mode `600`.
- Termux therefore uses `trusted.gpg.d` keyring symlinks, **not** per-source
  `Signed-By`, as its shipped design.

**Implementation decisions that depend on this source:**
- `templates/termux/sources.list` uses the legacy one-line format with the
  primary host and `stable main` (Termux does not ship deb822 defaults).
- `lib/platforms/termux.sh` validates keyring presence at
  `$PREFIX/etc/apt/trusted.gpg.d` and `$PREFIX/share/termux-keyring`, and treats
  a symlink whose target is inside `$PREFIX/share/termux-keyring` as expected
  rather than as an unsafe symlink (`lib/quarantine.sh` allowlist).
- The project never writes `Signed-By:` for Termux, and never adds Debian
  keyring paths there.
- `termux-change-repo` (from `termux-tools`) is named in the operator guide as
  the supported way to switch mirrors; this project does not select mirrors.

### 3.2 Kali Linux — `primary`

| Field | Value |
| --- | --- |
| Source | `kalilinux/documentation/kali-docs`, `general-use/kali-apt-sources/index.md` (the source of the blocked `kali.org/docs` page), author `g0tmi1k` |
| URL | https://gitlab.com/kalilinux/documentation/kali-docs/-/raw/master/general-use/kali-apt-sources/index.md |
| Retrieved | 2026-08-06 |

Verbatim, for a clean install with network access:

```
# /etc/apt/sources.list.d/kali.sources
Types: deb
URIs: http://http.kali.org/kali/
Suites: kali-rolling
Components: main contrib non-free non-free-firmware
Signed-By: /usr/share/keyrings/kali-archive-keyring.gpg
```

Pre-2026.2 installations instead carry, in `/etc/apt/sources.list`:

```
deb http://http.kali.org/kali kali-rolling main contrib non-free non-free-firmware
```

Further conclusions used:

- Since **Kali 2026.2** the network repositories live in
  `/etc/apt/sources.list.d/kali.sources` (deb822). Before that the file did not
  exist.
- Main branches are `kali-rolling` (default) and `kali-last-snapshot`
  (quarterly point release). Additional branches `kali-experimental` and
  `kali-bleeding-edge` exist and are managed with `kali-tweaks`.
- `apt modernize-sources` is the vendor-sanctioned legacy→deb822 conversion and
  writes `.list.bak` backups.

**Implementation decisions that depend on this source:**
- `templates/kali/kali.sources` is deb822 with exactly the four components and
  the `Signed-By` path above; `templates/kali/sources.list.legacy` holds the
  one-line form for pre-2026.2 systems.
- `lib/platforms/kali.sh` selects the deb822 template when
  `/etc/apt/sources.list.d/kali.sources` already exists **or** the detected Kali
  release is `>= 2026.2`, otherwise the legacy template — it never invents a
  migration the vendor did not perform.
- The rebuild preserves the detected branch suite (`kali-rolling` vs
  `kali-last-snapshot`) instead of forcing `kali-rolling`, satisfying "never
  silently move a system between releases/channels".
- `kali-experimental` / `kali-bleeding-edge` are never added by this project;
  if present they are preserved and reported, and the operator is pointed at
  `kali-tweaks`.

### 3.3 Parrot OS — `primary` (repository lines), `secondary` (keyring mechanism)

| Field | Value |
| --- | --- |
| Source | `ParrotSec/parrot-core`, `system_configs/apt/sources.list.d/parrot.list` |
| URL | https://raw.githubusercontent.com/ParrotSec/parrot-core/master/system_configs/apt/sources.list.d/parrot.list |
| Retrieved | 2026-08-06 |

Verbatim active lines:

```
deb https://deb.parrot.sh/parrot echo main contrib non-free non-free-firmware
deb https://deb.parrot.sh/direct/parrot echo-security main contrib non-free non-free-firmware
deb https://deb.parrot.sh/parrot echo-backports main contrib non-free non-free-firmware
```

The file's own comments state the security repository should **always** be
enabled and should **not** be served from mirrors (official domains/CDN only —
hence the `/direct/` path), and that backports may be disabled if stability is
preferred over newer features.

Supporting: Parrot 7.0 "Echo" was released 2025-12-24 (search summary,
`secondary`), which is consistent with the `echo` suite in the upstream file.

**Implementation decisions that depend on this source:**
- `templates/parrot/parrot.list` reproduces the upstream file's active lines,
  with `echo-backports` **commented out by default** — a deliberate,
  documented deviation toward stability that the operator can enable with
  `SDB_PARROT_ENABLE_BACKPORTS=1`.
- The security line keeps the `deb.parrot.sh/direct/` host exactly as upstream
  writes it; the project must not "normalize" it to the mirror director.
- Upstream `parrot.list` carries **no** `Signed-By`; Parrot relies on
  `parrot-archive-keyring` in `trusted.gpg.d`. The exact keyring filename could
  not be confirmed from a primary source, so `lib/platforms/parrot.sh` verifies
  that *some* Parrot keyring is present in `trusted.gpg.d` and **reports**
  rather than writing a `Signed-By` line this build cannot verify.
- The suite (`echo`) is templated as `@PARROT_SUITE@` and defaults to the suite
  discovered on the running system; the upstream value `echo` is used only when
  nothing can be discovered, and then only with operator confirmation.

`/usr/share/keyrings/` contains `ubuntu-archive-keyring.gpg`,

| Field | Value |
| --- | --- |
| Source | Ubuntu Community Hub, "[Spec] APT deb822 sources by default", Foundations team |
| URL | https://discourse.ubuntu.com/t/spec-apt-deb822-sources-by-default/29333 |
| Retrieved | 2026-08-06 |

Confirms the two-stanza layout (archive + security), `Signed-By` semantics, and
that deb822 became the default beginning with 24.04 LTS.

**Implementation decisions that depend on this source:**
- `templates/ubuntu/ubuntu.sources` is a two-stanza deb822 file parameterised on
  `@CODENAME@`, with `archive.ubuntu.com` and `security.ubuntu.com`.
- The component set is **preserved from the system being repaired**, not forced:
  a system with only `main universe` keeps `main universe`. The template default
  (`main universe restricted multiverse`) applies only when nothing can be
  recovered from backup/inventory.
- `-backports` is included only if it was already enabled.
- `-proposed` and development suites are never written (`lib/platforms/ubuntu.sh`
  rejects them as an unsupported suite and stops).
- Architecture-qualified `Signed-By` is not used; the single archive keyring
  path above is used for both stanzas.

### 3.5 Debian — `secondary` (shipped file), `primary` (release/EOL data)

Direct Debian documentation was policy-blocked. Search summaries of
`wiki.debian.org/SourcesList` and of the Debian 13 deb822 migration consistently
describe the shipped `/etc/apt/sources.list.d/debian.sources` as stanzas with
`URIs: http://deb.debian.org/debian/` and
`http://security.debian.org/debian-security/`, `Suites: trixie`,
`trixie-updates`, `trixie-security`, and
`Signed-By: /usr/share/keyrings/debian-archive-keyring.gpg`, with
`apt modernize-sources` as the conversion tool. Rated `secondary`.

Corroborating `primary` data from the build host's `distro-info-data`
(`/usr/share/distro-info/debian.csv`), read-only:

```
12,Bookworm,bookworm,2021-08-14,2023-06-10,2026-09-12,2028-06-30,2033-06-30
13,Trixie,trixie,2023-06-10,2025-08-09,2028-08-09,2030-06-30,2035-06-30
14,Forky,forky,2025-08-09
15,Duke,duke,2027-08-01
```

Conclusions: Debian 13 `trixie` is stable (released 2025-08-09); `bookworm` is
oldstable and, as of the research date, still inside its regular security window
(which closes 2026-09-12, with LTS to 2033-06-30); `forky` is testing and `duke`
is future — neither is a valid repair target.

**Implementation decisions that depend on these sources:**
- `templates/debian/debian.sources` is marked `confidence=secondary`, so
  `--repair-repositories` on Debian **stops and requires
  `--allow-secondary-template`** with the exact reason printed. This is the
  fail-closed behaviour required when current repository information cannot be
  verified from the vendor.
- Release/EOL classification (`lib/repository-audit.sh`, `sdb_release_status`)
  reads `/usr/share/distro-info/*.csv` **at run time on the target host** when
  the `distro-info-data` package is present, rather than trusting any table
  baked in at build time. The values above are used only as a documented
  fallback table and are stamped with their retrieval date.
- `testing`, `unstable`, `sid`, `experimental`, and any suite whose codename is
  not the detected release are refused as repair targets.

### 3.6 MX Linux — `secondary`

Direct MX sources (`mxlinux.org/wiki/system/repos-mx-25/`, `mxrepo.com`) were
policy-blocked. Search summaries of the official MX-25 repos wiki page describe:

```
# /etc/apt/sources.list.d/mx.list
deb http://mxrepo.com/mx/repo/ trixie main non-free
#deb http://mxrepo.com/mx/testrepo/ trixie test
#deb http://mxrepo.com/mx/repo/ trixie ahs

# /etc/apt/sources.list.d/debian.list
deb http://deb.debian.org/debian trixie main contrib non-free
deb http://security.debian.org/debian-security trixie-security main contrib non-free non-free-firmware

# /etc/apt/sources.list.d/debian-stable-updates.list
deb http://deb.debian.org/debian/ trixie-updates main contrib non-free non-free-firmware
```

Further `secondary` conclusions: MX Linux 25 "Infinity" is based on Debian 13
trixie; MX 25.1 ships **dual init** — both SysVinit and systemd are available and
selectable at boot — so init must be detected, never assumed.

**Implementation decisions that depend on these sources:**
- MX is the clearest case of "must not mix distributions incorrectly" *and*
  "must not un-mix a legitimate combination": MX deliberately uses MX repos
  **plus** Debian stable repos. `lib/platforms/mx-linux.sh` therefore treats
  Debian archive entries on MX as expected, while the same entries on Kali or
  Parrot are flagged as foreign.
- MX templates are `confidence=secondary` → repair requires
  `--allow-secondary-template`.
- The MX mirror host is **preserved from the system** where discoverable
  (`mxrepo.com` is a redirector to community mirrors and operators commonly have
  a local mirror); the template value is a fallback only.
- Init is detected (`lib/detect-platform.sh`, `sdb_detect_init`) and every
  hardening control that requires systemd is skipped with an explicit
  "unsupported on this init" record rather than failing.

### 3.7 APT security behaviour — `primary` (local), `secondary` (docs)

`manpages.debian.org` was blocked; `sources.list(5)` was not read directly. The
following are established from the build host's own apt 2.8.3 and its shipped
configuration, and are used only in ways that are conservative if the doc detail
differs:

- deb822 field names in use on a shipping system: `Types`, `URIs`, `Suites`,
  `Components`, `Signed-By` (observed verbatim above).
- `apt-config dump`, `apt-get indextargets`, `apt-cache policy`, and
  `apt-get update` accept `-o Dir::Etc::sourcelist=`, `-o Dir::Etc::sourceparts=`,
  `-o Dir::Etc::trusted=`, `-o Dir::Etc::trustedparts=`, `-o Dir::State::lists=`
  and `-o Dir::Etc::main=` overrides, which is what makes **staged validation
  against a directory that is not the live configuration** possible. This is the
  mechanism used by `lib/repository-validate.sh`.

**Implementation decisions:** the project never uses `apt-key` (deprecated and
removed), never emits `[trusted=yes]` or `Trusted: yes`, never sets
`APT::Get::AllowUnauthenticated`, `Acquire::AllowInsecureRepositories`, or
`Acquire::AllowDowngradeToInsecureRepositories`, and treats the presence of any
of these in existing configuration as an audit finding.

`/usr/share/distro-info/ubuntu.csv` (build host, read-only), relevant rows:

```
24.04 LTS,Noble Numbat,noble,2023-10-12,2024-04-25,2029-05-31,2029-05-31,2034-04-25
25.04,Plucky Puffin,plucky,2024-10-10,2025-04-17,2026-01-15
25.10,Questing Quokka,questing,2025-04-17,2025-10-09,2026-07-09
26.04 LTS,Resolute Raccoon,resolute,2025-10-09,2026-04-23,2031-05-29,2031-05-29,2036-04-23
```

Cross-checked by search summary: Ubuntu 26.04 LTS "Resolute Raccoon" released
2026-04-23.

Conclusions used: as of the research date, `noble` and `resolute` are supported;
`questing` (25.10) reached EOL 2026-07-09 and `plucky` (25.04) on 2026-01-15 —
both are **EOL** and must trigger the stop-and-explain path, not an automatic
rewrite and not automatic `old-releases.ubuntu.com`.

**Implementation decision:** EOL handling is data-driven from the target host's
own `distro-info-data` when present; the fallback table in
`lib/repository-audit.sh` is explicitly dated and marked stale-able, and when
neither is available the release status is `unknown`, which is treated as
"refuse to rewrite" rather than "assume supported".

### 3.9 CIS / hardening guidance — `unverified`

CIS Benchmarks were not retrievable in this environment (they are not openly
fetchable and the relevant hosts were not reachable). **No control in
`lib/baseline-hardening.sh` claims CIS conformance, and no CIS control number is
cited anywhere in this project.** The baseline is limited to controls that are
(a) checkable on the running system, (b) reversible, and (c) justified by the
system's own documentation (`sshd_config` semantics, `sysctl` names present on
the host, `dpkg --verify`, `find -perm` checks). Anything requiring an external
benchmark to justify is implemented as a **report-only finding**, never an
automatic change.

## 4. Facts deliberately NOT used

The following were *not* established to any usable confidence and are therefore
absent from the code rather than guessed:

- Exact filename of Parrot's archive keyring under `trusted.gpg.d`.
- Whether MX 25 ships deb822 `.sources` by default in addition to `.list` files
  (search output was ambiguous: "also supports"). The MX template writes the
  `.list` form, which is unambiguously supported.
- Any Termux `Signed-By` layout (upstream uses `trusted.gpg.d` symlinks).
- Current MX mirror hostnames other than the `mxrepo.com` redirector.
- Kali mirror hostnames other than the `http.kali.org` redirector.
- Any third-party or PPA repository content whatsoever — out of scope by design.
